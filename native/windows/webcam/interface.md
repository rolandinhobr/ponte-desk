Windows webcam interface (initial version)

- Rust: `start(width,height,fps) -> Result<Box<dyn super::Sink>,String>`; Sink has push(&[u8])->Result and stop(). No additional Cargo dependencies. Call start/push/stop/drop on the same thread (COM affinity). Do not mark sink Send.
- Capture preferences: 1280x720 or 1920x1080 at 30fps. The virtual source advertises NV12 and RGB32 at both sizes, defaulting to 1920x1080; the consumer can select either. JPEG input accepts exactly either known size, maximum 2,097,152 bytes. WIC metadata validation rejects unsupported sizes before publication; WIC scales to the format selected by the consumer.
- DLL C ABI uses cdecl. HRESULT PonteWebcamStart(UINT width,UINT height,UINT fps,void** session); HRESULT PonteWebcamPush(void*,const BYTE*,UINT); HRESULT PonteWebcamStop(void*). Nonnegative HRESULT means accepted; S_FALSE on push means no consumer mapping or a contended slot, so latest frame can be dropped.
- Installation: elevated install.ps1 copies the static-runtime source DLL under Program Files/PonteDesk/Webcam and registers this CLSID: {93E78377-4F8D-45DB-A4B7-618B2271189A}. No kernel driver, OBS, tray helper or resident process.
- Source registration is machine-level because Windows FrameServer services load it. Its data-section ACL permits only the installing user's SID, SYSTEM and Local Service. FrameServer can use a Global section; an ordinary same-session source client falls back to Local only when Global section creation lacks permission (5/1314). The producer opens existing sections and publishes to both when needed. At most two bounded slots (~4MiB) exist. Current-user/session virtual camera registration occurs only on start; stop unregisters it.
- Default DLL path is %ProgramFiles%/PonteDesk/Webcam/PonteDeskWebcam.dll. PONTE_DESK_WEBCAM_DLL overrides it for isolated tests.
- Windows app picker name includes Ponte Desk Camera; Windows appends "Windows Virtual Camera" automatically.
- Latest JPEG is exchanged in bounded anonymous shared memory (no image files); no queue accumulation. Stale input (>2 seconds), stop, or invalid JPEG yields a black image. No network is handled in this DLL; common Rust transport authenticates/authorizes peers before calling push.
- Idle: zero controller threads/timers; no camera capture. MF RequestSample drives decoding only while a Windows camera consumer requests frames. Closing an active session removes the virtual camera and clears shared input.
- If MFCreateVirtualCamera returns E_ACCESSDENIED due to Windows privacy settings, show the error and request the user's action; do not modify camera privacy registry settings.
