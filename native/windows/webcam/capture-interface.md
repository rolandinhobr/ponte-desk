Windows physical capture interface

- `list() -> Result<String,String>` returns `{"devices":[{"id":"opaque symbolic link","name":"device name","external":true}]}`. Metadata enumeration only; it never opens a camera.
- `start_capture(device_id:&str, format:super::Format) -> Result<Box<dyn super::Capture>,String>`. Capture implements `copy_jpeg(&mut self, &mut [u8]) -> Result<usize,String>`; zero means no frame within 250ms. Drop stops/flushed MF source. No Cargo dependencies. COM calls stay on one thread.
- Only the exact explicitly selected ID may open; it is re-enumerated/revalidated before opening. SetupAPI requires a USB bus and removable physical USB devnode in the bounded ancestry; unknown or nonremovable metadata is excluded. Thus virtual cameras and builtins are not used as fallbacks. Some OEM devices with incomplete metadata may be excluded.
- Formats: 1280x720 or 1920x1080 at 30fps; JPEG up to 2MiB. SourceReader selects a real native format with matching dimensions and nominal30fps (29.8–30.2 tolerance), preferring MJPEG. It applies IMFSourceReaderEx::SetNativeMediaType before output conversion and verifies actual output dimensions/subtype. Otherwise RGB32 output at that same native size is converted to JPEG with WIC; a640x480 source is never upscaled to claim1080p. Latest async MF sample replaces the old one; there is no accumulating frame queue.
- C ABI: PonteCaptureList(char*,UINT,UINT* requiredBytes), PonteCaptureStart(const WCHAR* id,UINT width,UINT height,UINT fps,void**), PonteCaptureCopy(void*,BYTE*,UINT capacity,UINT* length), PonteCaptureStop(void*); all return HRESULT and use cdecl. List includes a terminating NUL in requiredBytes. List can be called with null output to size the buffer.
- Transport, peer authorization and explicit user controls remain in the common Rust module. The DLL opens no network sockets and creates no image files.
- Physical USB webcam capture passed under a standard-user token: ten real JPEGs at1920x1080 and ten at1280x720, dimensions confirmed through WIC, nonuniform image statistics, start/copy/stop HRESULT0. No frames were written to disk. Full Windows-to-Mac virtual-camera consumer verification is reported separately.

Native callback safety: the DLL is pinned in the sender process only after an explicit physical camera has opened and before creating asynchronous SourceReader callbacks. This retains approximately 560KiB of code until that same sender process exits; it creates no extra worker/app and consumes no idle CPU. Metadata enumeration and invalid-device rejection do not pin the module.
